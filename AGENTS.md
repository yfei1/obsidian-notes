# Obsidian Notes — Agent Guidelines

## User Content & Code Examples Preservation

- **Faithfully Record All User Insights & Code**: All conversation insights, architectural discussions, mathematical derivations, real-world analogies, and concrete code examples provided by the user must be faithfully written and preserved in the relevant canonical notes. Never discard user-provided code examples or replace them with abstract summaries.

## Zero Knowledge Loss on Rewrites

- When rewriting or restructuring a note, **never delete factual content**. Restructure, don't remove.
- If content is moved to another file, ensure the destination file actually contains the full explanation before trimming the source.
- **One Canonical Home**: Each concept has exactly ONE canonical note. Other notes reference it with a brief summary and wikilink.

## File Size & Structure Limits

- **Target line count**: 250–300 lines.
- **Soft cap**: 350 lines (acceptable for complex topics).
- **Hard split**: 400 lines (MUST split into sub-notes).
- **Format**: Pair code with output; define terms at first use; ensure all wikilinks are strictly bidirectional.
